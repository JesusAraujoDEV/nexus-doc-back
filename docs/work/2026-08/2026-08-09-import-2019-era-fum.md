# 2026-08-09 — Import F.U.M. from the CONSULTA_2019 era

## What changed
`scripts/import-legacy-pregnancies-2019.js` imports real F.U.M./gesta/status from `CONSULTA_2019/EMBARAZO.DAT` (1,721 rows, the older of the two legacy eras) onto the already-backfilled `pregnancies` table. 1,621 of 1,721 updated. Combined with the same-day `CONSULTA_2021_v2` import (576 rows), **2,197 of 2,295 pregnancy episodes (95.7%) now carry a real F.U.M.**

## Why
Explicit follow-up the user asked for directly: after the `CONSULTA_2021_v2` F.U.M. import landed, the user asked "espero que los datos de las embarazadas lo hayas sacado tambien de la 2019, que es la data antes de 2020" — they had not; this closes that gap.

## How
`CONSULTA_2019` is a genuinely separate legacy numbering sequence from `CONSULTA_2021_v2` (confirmed in the same-day `pregnancy-backfill-correction` work: `patients.legacy_record_id` reflects the `CONSULTA_2021_v2` era's `PACIENTE.DAT` codes, not `CONSULTA_2019`'s), so this import can't reuse the same patient-matching approach as the `2021_v2` script:

- **Patient matching**: cross-referenced via `CEDULA`, not code. Extracted a `CODIGO -> CEDULA` crosswalk from `CONSULTA_2019/PACIENTE.DAT` (`data/scripts/analisis/25_extraer_paciente_cedula.js`, 5,744 usable cédulas out of 5,778 patients) and joined `EMBARAZO.DAT`'s `PACIENTES` code through that to `patients.cedula`. Skipped rows whose cédula is duplicated within the 2019 file (5 collisions, unusable for a reliable match) or where no patient carries that cédula today.
- **Episode matching**: NOT by the legacy `EMBARAZOS` code (already proven to collide 33% of the time across eras, see the same-day correction entry) — matched a patient's pregnancy episode by date instead: the episode is a candidate only if it has a linked `clinical_records.visit_date` within ±300 days of the legacy row's F.U.M. Rows with zero or more than one candidate episode in range are skipped rather than guessed (69 had multiple, 1 had none) — a false match on 1,621 real pregnancies is a worse outcome than 70 unmatched ones.
- **`legacy_code` deliberately left null for every row imported this way** — the 2019 era's own `CODIGO` (1–1,721) overlaps the same numeric range the `2021_v2` import already used for `legacy_code` (1–579, on a `UNIQUE` column), so storing it here would either collide or require namespacing the column, out of scope for a one-off backfill.
- Same non-destructive guard as every prior pregnancy-data script: only updates a ficha if it's still provably untouched (`updated_at = created_at`, `lmp_date`/`newborn_data` still null) — 1 row was already hand-edited since the last backfill and correctly skipped.

## Promoted knowledge
Cross-era patient matching by cédula (not by any legacy numeric code) is now the established fallback whenever `legacy_record_id` doesn't apply to the era being imported — see `data/scripts/analisis/25_extraer_paciente_cedula.js`.
